# 시험 DB 다중 카테고리 저장 — 2026-11-22

## 승인 범위
사용자가 2026-11-22 **격리된 시험 Supabase**에 카테고리·모드 연결 테이블과 본인 전용 RLS/권한을 추가하고 기능을 테스트하는 작업을 승인. 운영 DB, 기존 모드 데이터, 운영 배포, main 병합, UI 디자인 변경은 제외.

## 적용 결과
- 시험 프로젝트 `smofdbjgcgdmscamknpw`에 마이그레이션 `test_mod_categories_owner_rls` 적용 성공.
- `categories`: 소유자별 카테고리 정의(이름, 순서). `mod_categories`: 한 모드의 다중 소속. `mod_category_primary`: 분류된 모드당 대표 카테고리 1개. 분류되지 않은 기존 모드는 연결 0개·대표 0개로 유지.
- 지연 FK 및 지연 제약 트리거로 대표 카테고리가 실제 소속 카테고리에 속하도록 하고, 카테고리가 하나라도 있는 모드는 대표 1개를 요구한다. 소유자 불일치 차단.
- `save_mod_categories(uuid,uuid[],uuid)`: `SECURITY INVOKER`와 RLS 기반 원자적 교체. 1~64개, 중복 불허, 대표 포함 필수, 다른 소유자의 모드·카테고리 불허. DB 소유자 직접 권한은 최소 범위로 제한.
- `GET/POST /api/categories`, `GET/POST /api/mod-categories`: 기존 인증·허용 사용자 검사. 읽기는 소유자 전용, 쓰기는 **시험 Preview 브랜치 + 시험 Supabase + 명시적인 별도 환경 변수 `MOD_CATEGORY_TEST_WRITE_ENABLED=true`가 모두 일치할 때만** 허용. 현재 별도 쓰기 플래그는 설정하지 않음. 기존 화면 변경 없음.
- 순수 입력 검증 테스트 4개 추가. SQL 실사용 테스트: 임시 가상 모드/카테고리 생성→2개 연결→대표 선택→중복·대표 미포함 차단→대표 교체→트랜잭션 `ROLLBACK`. 확인 후 `categories=0`, `mod_categories=0`, `mod_category_primary=0`, `mods=0`. 기존 연구 대기함 변경 없음.
- **미완료:** 실제 로그인 브라우저에서 API POST/GET E2E, 사용자가 조작할 카테고리 관리 UI(별도 디자인 승인), 태그/선택 그룹 영구 저장, 운영 적용.
- **중요 백업 제약:** 기존 JSON v3는 10개 데이터 영역만 포함하므로 **새 카테고리 3개 테이블은 아직 백업에 포함되지 않는다**. 카테고리 실사용·운영 적용 전에 기존 v3를 '전체 DB 복구 가능'으로 설명하지 말고, 후속 백업 포맷 확장/검증이 필요하다.
