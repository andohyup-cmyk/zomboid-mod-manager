# 모드 다중 카테고리 + 대표 카테고리 설계

결정: **2026-11-21 사용자 승인 B안**.

## 확정

- 하나의 모드는 **카테고리 여러 개**에 속할 수 있다.
- 선택된 카테고리 중 **대표 카테고리 정확히 하나**를 지정한다.
- 태그는 여러 개이며 카테고리와 별도 개념이다.
- 선택 그룹은 카테고리·태그와 독립이다. 선택 그룹의 기본 규칙은 **자유 선택**으로 확정됐다. 필수·배타 규칙은 개별 그룹에서 명시적으로 설정한 경우에만 적용한다.
- 대표 카테고리는 목록 표시 및 향후 추천 정렬의 기준이 될 수 있다. **실제 서버 로드 순서를 자동 변경하지 않는다.**
- 사용자 지시 전 홈·모드·서버 UI 디자인은 변경하지 않는다.

## 현재 코드

- `lib/mod-category-assignment.ts`: 카테고리 1~64개, 중복 없는 식별자, 대표 카테고리 포함을 검사하는 순수 검증 함수.
- `tests/mod-category-assignment.test.ts`: 다중 소속, 대표 선택, 중복·빈값·오류 방지, 원본 배열 보존 검사.
- 아직 DB·API·UI에서 이 검증 함수를 사용하지 않는다. **데이터 저장이 구현됐다는 뜻은 아니다.**
- 카테고리 수 64개와 식별자 최대 128자는 검증 단계의 임시 안전 한도이며 제품 정책 확정이 아니다.

## 추후 DB 설계 제안 (미적용)

기존 `mods` 테이블은 대표 카테고리의 연결을 갖고, `mod_categories` 조인 테이블은 모든 소속 카테고리를 저장한다. `categories`는 사용자별 카테고리 정의를 저장한다.

- `categories`: `id`, `owner_id`, `name`, `sort_order` 등
- `mod_categories`: `owner_id`, `mod_id`, `category_id`, 유일한 `(mod_id, category_id)`
- 대표 카테고리 연결은 반드시 `mod_categories`에 존재해야 한다. 단일 `mods.primary_category_id` FK만으로는 이 포함 조건을 보장할 수 없으므로, 복합 FK·지연 제약·서버 트랜잭션 등 안전한 방법을 마이그레이션 단계에서 결정한다.
- 모든 쓰기는 사용자 본인 소유 레코드로 제한한다. 기존 승인된 조사/등록 경로와 분리하고 카테고리 값으로 B42.22 호환성을 자동 확정하지 않는다.
- 마이그레이션 시 이미 존재하는 미분류 모드와 대표 카테고리의 초기값 정책을 검토한다. **현재 테스트 DB에서 카테고리 관련 테이블이나 권한을 생성하지 않았다.**

## 구현 전 별도 승인

- 새 테이블/외래키/RLS/GRANT/기존 레코드 마이그레이션은 DB 스키마·권한 변경에 해당하므로 사용자 별도 승인 필요.
- 운영 배포와 main 병합도 별도 승인 필요.
- UI 변경은 사용자가 조건을 제시할 때 진행.
