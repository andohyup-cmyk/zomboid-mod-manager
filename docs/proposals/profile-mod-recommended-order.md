# 서버 프로필 추천 정렬 미리보기

대상은 Project Zomboid B42.22 서버 프로필이다. 작성자의 공개 설명에서 카테고리 묶음과 위상 정렬, 정렬 규칙의 방향과 범위를 참고했다. 이 구현의 같은 우선순위 처리에는 프로필의 기존 상대 순서를 사용한다. B42.22 실제 로드 결과는 별도 검증 항목이다. [Steam Workshop 설명](https://steamcommunity.com/sharedfiles/filedetails/?id=3423660713) · [작성자의 Sorting Rules](https://steamcommunity.com/workshop/filedetails/discussion/3423660713/592888629473368243/)

## 입력

- `recommendProfileModOrder(selections, { categoryPriority, rules })`는 기존 편집 상태 `ProfileModSelection[]`을 읽는다. `categoryPriority`는 우선순위가 높은 카테고리 ID부터 전달한다. 빠진 카테고리와 미확인 카테고리는 가장 낮은 우선순위에서 기존 순서를 기준으로 비교한다.
- `rules`는 앱 내부의 구조화된 관계 데이터다. 주체 `mod`와 상대 `target`을 지정할 때 가능하면 `{ workshopId, modId }`를 사용한다. 문자열 Mod ID만 제공하면 선택 목록 전체에서 유일해야 한다. 동일 문자열을 제공하는 여러 Workshop이 있으면 후보를 경고에 담는다.
- 규칙을 사용하려면 호출자가 `evidence.verified`를 `true`로 지정하고 출처 `source` 또는 확인 기록 `verificationNote`를 제공해야 한다. 확인 날짜가 있으면 `checkedAt`에 함께 전달한다. 경고와 규칙 기반 이동 이유에서 이 근거를 읽을 수 있다.

## 규칙

| 규칙 | 미리보기 동작 |
| --- | --- |
| `loadAfter` · `loadBefore` | 활성 항목 사이에 방향이 있는 제약을 만든다. 명시적 제약을 만족하면서 현재 배치 가능한 항목 중 카테고리 우선순위, 기존 위치 순으로 고른다. 상대가 누락·비활성이면 검토 경고를 표시한다. |
| `loadFirst` · `loadLast` | `scope: "on"`은 전체 활성 목록, `"category"`는 같은 대표 카테고리의 활성 항목, `"off"`는 적용 해제다. 같은 범위에서 앞 또는 뒤 위치를 공유하는 항목은 같은 묶음으로 대우한다. 카테고리가 미확인이면 카테고리 범위 규칙을 건너뛰고 경고한다. |
| `requires` | 명시적으로 확인된 필수 의존 대상의 활성 여부를 검사한다. 누락·비활성·모호한 필수 의존성은 추천을 차단한다. 필요 여부와 선행 여부는 별도 규칙으로 표현한다. |
| `incompatibleMods` | 두 대상이 활성이고 식별이 명확하면 경고한다. 순서 제약에는 반영하지 않는다. |

확인된 위치·선행·후행 규칙으로 순환이 발생하면 추천 목록은 `null`이고, 실제 순환 경로 한 개와 그 경로의 근거를 반환한다. 동일 Workshop ID와 Mod ID 쌍이 목록에 반복될 때도 추천을 차단한다. 비활성 행은 그래프에 들어가지 않으며, 계산 결과는 기존 활성 행의 자리에만 배치한다. 비활성 행의 번호와 값은 유지한다.

원본 모드의 알파벳 동률 처리, 원본 규칙 파일 및 `mod.info`의 텍스트 파싱, 버전별 필드 해석은 범위 밖이다. 현재 입력은 출처가 확인된 구조화 규칙을 전제로 한다.

## 모바일 화면 연동

서버 프로필 편집의 선택한 모드 탭에서 추천 정렬을 누르면 현재 편집 목록을 전달한다. 각 항목의 기존·추천 번호와 이동 이유를 비교 표에 보여 준다. 이동 이유는 기존 순서를 바로잡은 규칙, 카테고리 우선순위가 반영된 교차 이동, 또는 다른 이동으로 인한 위치 변화로 표시한다.

`ready`는 공급된 규칙에서 경고 없이 미리보기 계산이 끝났다는 뜻이다. `needs-review`는 미리보기와 함께 경고 검토가 필요하다는 뜻이다. `blocked`에서는 현재 목록과 차단 이유만 보여 준다. 편집 목록 또는 옵션이 바뀌면 기존 미리보기를 무효화한다. 추천 순서 적용을 눌렀을 때만 임시 목록을 바꾸고, 확정은 기존 변경사항 확인으로 진행한다.

읽기 전용 카탈로그 화면은 현재의 DB 스키마에서 대표 카테고리·정렬 규칙을 공급하지 않는다. 따라서 이 입력으로 추천을 요청하면 기존 순서를 유지한다. 확인된 관계 데이터 공급과 실제 B42.22 로드 검증은 후속 작업이다. 예시 정렬 관계를 주입하는 테스트 화면에는 예시 규칙 표시를 사용한다.
